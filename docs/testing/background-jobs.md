# 后台与定时任务

在流程编辑器点击“定时执行”。编辑器先保存当前流程，再打开任务表单；保存期间切换流程或产生新编辑会停止操作。可以选择未来的一次性时间，或指定 Cron、IANA 时区、错过执行时间后的策略，并填写流程输入、尝试次数、超时、优先级及 Agent 配置。

Cron 使用六段或七段表达式，第一段是秒。例如 `0 0 9 * * *` 加 `Asia/Shanghai` 表示北京时间每天 09:00。应用必须运行才能执行；恢复后可选择补跑一次或跳至下一次。一次性时间使用本机时区输入，保存为 UTC。

能力中心的“任务”可编辑尚未开始的排队或暂停任务。已开始、重试中、等待审批或结果不确定的任务保留原计划，不能改写。编辑带版本检查，其他操作先更新任务时会要求刷新，避免覆盖。新任务保存主流程、引用的子流程和 Skill 的来源快照，执行与重启恢复使用冻结的源码；声明文件依赖保存内容哈希，发生变化时停止执行。能力版本校验仍会拒绝与原计划不符的审批。

运行中会在派发节点前持久化检查点，完成后保存输出。重启后沿用同一个运行编号并复用完成节点，后续节点继续读取其输出。不能确认是否发生的副作用标记为“核验执行结果”，不会自动重做。请先检查外部系统：确认未发生才允许重试，确认已完成则填写真实的 JSON 输出。旧版缺少结果或版本绑定的检查点只能在确认未发生后重试。

需要审批时任务释放工作租约，等待期间不消耗失败重试。能力中心任务详情可批准或拒绝；L3 操作还需二次确认。重启后的审批仍绑定原计划、能力版本和参数结构。部分批准时保持等待，批准全部待处理节点后才继续。

点击“查看运行”可看本轮结果。重复任务进入下一轮后仍能查看前一轮结果，完整运行记录可在 Mission Control 历史中查看。“跟随最新运行”返回实时视图。历史运行的控制请求绑定运行编号，不能误操作同一个重复任务的下一轮。

恢复会扣除已持久化的所有调用尝试及其已知用量，包括失败、取消和超时。嵌套流程分别记账，避免重复累计；活动耗时按各尝试的总和保守累计，离线及审批等待不计。未返回用量的外部调用标记为“用量未知”，预算敏感任务会暂停；在运行详情核对后填写 Tokens、费用和原因，再恢复执行。人工对账保留修订版本，不能将金额降至已知费用以下。

动态流程引用只允许指向已捕获的项目内来源，动态 Skill 引用同样绑定快照。需要校验版本的其他本地文件通过流程 `spec.dependencies` 声明；未声明的数据文件、网络端点和外部系统状态仍由运行时读取。旧版任务没有来源快照时继续使用原有版本校验，不会自动改变历史计划或审批哈希。
