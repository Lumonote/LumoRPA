# 节点画布分析与开发记录

日期：2026-11-10。开发基于主目录的 `dev` 分支。

用户选择 ComfyUI 方向：高密度、端口明确、连线能力优先。目标是让“添加节点 → 配置参数 → 连接数据 → 执行 → 定位结果”形成连续操作路径。LumoRPA 的 YAML 仍是结构化顺序程序；画布必须准确表达现有执行语义。

## 本轮发现及完成的改造

| 原有断点 | 本轮实现 | 实际作用 |
| --- | --- | --- |
| 图主要是纵向步骤列表的投影，节点信息、执行顺序、数据依赖混在一起 | 横向节点工作台；石墨底色、点阵网格、紧凑卡片；执行口用青色菱形，数据口用琥珀色圆点 | 能直接区分“先执行谁”和“参数来自谁” |
| 只展示已有参数，缺失的必填参数难以发现 | 按动作 Schema 补齐输入口，展示类型、必填标记、当前值和未设置状态 | 不打开属性也能看见需要配置的输入 |
| 连线与实际源码脱节 | 数据连线写入真实 YAML 表达式；覆盖现有值先确认；可精确断开；执行连线在同级分支内重排完整节点子树 | 编辑结果能保存和运行，撤销可以恢复源码 |
| 连线可能制造未来结果引用或错误分支依赖 | 校验自连、顺序、分支、重复 ID 和重排后的数据依赖；含横线的 ID 使用下标表达式 | 在编辑时解释失败原因，降低运行时才发现错误的概率 |
| 添加动作需要离开画布，空画布无明显入口 | 搜索添加、双击空白添加、从动作列表拖入落点、点击执行边插入 | 创建流程可以持续在画布上完成 |
| 拖动不断重建节点，节点位置在插入后套到别的步骤 | 每帧合并几何更新，增量更新节点和边；布局键包含祖先 ID 与分支身份 | 拖动过程更稳定，源码重排后位置仍属于原节点 |
| 多选、拖动和撤销之间不一致 | 框选、修饰键多选、组拖动；布局与源码一起进入撤销/重做历史；旧手势按文档和修订失效 | 布局操作可以恢复，切换流程不会写回旧拖动 |
| 历史运行与当前源码容易串色 | 用流程路径、源码和 runId 限定执行态；匹配真实分支/循环运行路径 | 当前节点能显示状态与耗时，同名子节点不互相覆盖 |
| 属性面板挤占画布，重选节点会丢属性草稿 | 专注画布模式，窄屏属性抽屉；同一节点重复选中保留未应用草稿；重绘恢复端口焦点 | 大屏和窄屏都能连续编辑 |
| 异常 YAML 别名可能造成递归展开 | 祖先对象循环引用停止扩张，合法跨分支共享对象仍分别展开；循环参数摘要可安全展示 | 画布投影不会因循环别名无限递归；这不表示此类流程可以执行 |

运行中更改源码会使旧运行高亮失效。运行态展示覆盖当前流程运行路径；浏览历史记录不会给另一个文档染色。

## 实现边界

当前沿用静态 ESM 与 SVG/foreignObject，未引入 React Flow 等运行框架。前端没有打包器，现有 YAML 编辑器已具备 Parser span、属性编辑和执行接口；保留这些接口能减少迁移风险。代码拆成纯投影模型、源码编辑、连线规则、运行态和界面交互，后续可以独立替换布局或渲染层。

- `graph-model.js`：节点、端口、执行边/数据边、稳定布局身份。
- `graph-connections.js`、`graph-sequence.js`、`graph-editing.js`：数据绑定、执行顺序和保留未知字段的源码变更。
- `graph.js`、`graph-markup.js`、`graph-viewport.js`：渲染、几何和视口。
- `graph-interactions.js`、`graph-connect-ui.js`、`graph-palette.js`：手势、确认和动作添加。
- `graph-run-state.js`：将当前运行事件/报告映射到当前文档节点。
- `graph-studio.css`：节点工作台、端口、主题、抽屉和专注模式。

执行重连目前只重排同一个步骤列表。数据连接目前只创建同级前向绑定，来源 ID 必须全流程唯一；复杂条件、跨分支汇合和复合表达式仍使用属性或代码编辑。`control.parallel.do` 每项分别对应真实的并行分支，不能把列表外观误认为同一分支顺序执行。

布局保存在本机 localStorage，尚未进入可跨机器同步的项目文档。80 个节点的适应视图已验收，但不能据此推断千级节点的交互帧率或内存表现。

## 后续开发顺序

| 顺序 | 功能 | 设计要求与验收条件 |
| --- | --- | --- |
| 1 | 分组、命名、颜色与折叠 | 控制节点可以收起子树；用户可创建视觉分组；折叠后保留边界连接、运行状态和选中定位；不改变 YAML 执行语义 |
| 2 | 缩略导航与全局节点搜索 | 缩略图显示视口，可点击定位；按 ID、动作、参数搜索并聚焦；80 节点样例能快速定位目标并回到原视口 |
| 3 | 节点内结果预览 | 为文本、表格、图像和文件提供有界预览与展开入口；标注所属运行；源码变化后提示结果来源；大结果分页/截断且不撑开所有节点 |
| 4 | 端口类型和字段级绑定 | 动作 Schema 区分输入/输出结构；兼容口高亮，冲突解释；支持结果字段选择；嵌套字段与数组编辑保留未知内容 |
| 5 | 连线组织与自动布局 | 增加 reroute 中继点、对齐吸附与避让；分支汇合更清楚；拖拽到边上插入后自动修复相邻连接，布局可撤销 |
| 6 | 多节点复用与布局持久化 | 复制/粘贴时重写 ID 与组内引用；增加可版本化的项目布局格式、导入导出和旧缓存迁移 |
| 7 | 规模与原生闭环验收 | 固定 80/300/1000 节点基准，采集拖动帧耗时/长任务/内存；在 Tauri 中验证真实“编辑 → 保存 → 执行 → 结果 → 修改 → 再运行” |

节点预览和端口类型需要后端输出契约支持；优先在现有执行报告上补接口定义，再开发展示，避免仅凭外观推断结果结构。分组/缩略图可以在当前纯投影模型上独立推进。
